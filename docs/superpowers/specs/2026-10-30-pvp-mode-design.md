# 사람 vs 사람(PvP) 로컬 모드 설계

## 의도 / 배경

현재 틱택토는 사람 vs 컴퓨터(쉬움/어려움)만 지원한다. 같은 기기에서 두 사람이
번갈아 두는 PvP 모드를 추가해, 컴퓨터 없이도 즐길 수 있게 한다.

## 목표 (Goals)

- 모드 선택 화면에 "사람 vs 사람" 옵션을 추가한다.
- PvP 모드에서는 클릭할 때마다 X/O가 번갈아 둔다 (사람이 두 번 연속 두거나
  컴퓨터가 자동 응수하는 일이 없어야 한다).
- 현재 누구 차례인지("X 차례" / "O 차례")를 화면에 표시한다.
- 게임 종료 시 결과 배너는 승자 기준("X 승리!" / "O 승리!" / "무승부")으로
  보여준다.
- "다시 시작" / "모드 변경" 버튼은 PvP에서도 동일하게 동작한다.

## 비목표 (Non-goals)

- 온라인/원격 대전은 다루지 않는다 (로컬 동일 기기 전제).
- PvP 전적 기록/저장/조회는 다루지 않는다.
- 플레이어 이름 입력, 선공/후공 선택 등 추가 커스터마이징은 다루지 않는다.

## 안티골 (Anti-goals)

- 기존 쉬움/어려움(vs 컴퓨터) 모드의 동작이나 전적 기록 로직을 바꾸지 않는다.

## 제약 (Constraints)

- 기존 프런트엔드 구조(`game-logic.js`/`ai.js`/`api.js`/`game.js`, 단일 IIFE,
  절차적 스타일)를 유지한다.
- 백엔드(`/api/results`, `/api/stats`, `Difficulty` enum 등)는 변경하지 않는다.

## 검토한 접근 방식

1. **기존 `game.js` 확장** — 모드 값에 `'PVP'`를 추가하고, 클릭 핸들러 안에서
   PVP일 때 컴퓨터 응수(`computerMove`)와 전적 저장(`submitResult`) 호출을
   건너뛰도록 분기한다. 기존 구조·스타일과 맞고 변경 범위가 가장 작다.
2. **턴/플레이어 로직을 전략 패턴으로 분리** — 모드별 "다음 수를 누가 두는가"를
   별도 객체로 추상화. 확장성은 좋으나 모드가 3개뿐인 현재 규모엔 과한 설계.
3. **PvP 전용 페이지/스크립트 분리** — HTML/CSS 중복, 전적 패널 등 공유 요소
   별도 관리 필요로 복잡도만 늘어남.

**선택: 1번 (기존 `game.js` 확장)** — 변경이 작고 기존 스타일을 그대로
따르면서 차례 표시와 결과 배너도 모드에 안 묶인 공통 로직으로 쉽게 넣을 수
있다.

## 결정된 동작 (how)

- 모드 선택 화면(`#difficulty-select`)에 "사람 vs 사람" 버튼을 추가한다.
  (버튼/섹션 id는 기존 `easy-button`/`hard-button` 패턴을 따르되, 실제
  id/라벨 문구는 빌더 재량.)
- `startGame`에 `'PVP'` 모드를 추가하고, 현재 차례(X/O)를 추적하는 상태를
  둔다. PvP가 아닌 기존 모드는 사람=X 고정, 컴퓨터=O 고정 동작을 그대로
  유지한다.
- 차례 표시 UI 요소를 보드 영역에 추가한다 (예: 배너 위 텍스트).
- `finishGame`은 PvP일 때 승자 기호(X/O) 기준으로 배너 문구를 생성하고,
  `submitResult` 호출을 생략한다. 기존 vs 컴퓨터 모드는 현재 문구("승리했습니다!"
  등)와 전적 저장을 그대로 유지한다.
- "다시 시작"은 같은 모드로 재시작, "모드 변경"은 모드 선택 화면으로 복귀 —
  기존 동작 재사용.

## 빌더에게 남기는 부분

- 버튼 id/문구, 차례 표시 UI의 정확한 위치와 마크업/CSS 세부사항.
- 상태 변수 명명 및 코드 조직 세부사항 (예: `currentMode`, `currentTurn` 등).
- 신규 JS 단위 테스트(`game-logic.test.js`/`ai.test.js` 또는 새 파일) 범위와
  위치.

# 사람 vs 사람(PvP) 로컬 모드 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 같은 기기에서 두 사람이 번갈아 두는 PvP 모드를 모드 선택 화면에 추가한다.

**Architecture:** 기존 단일 `game.js` IIFE를 확장한다. 순수 로직(턴 교대, 결과 메시지 생성)은 `game-logic.js`에 함수로 추가해 node 테스트로 검증하고, DOM 배선(`game.js`)은 기존 프로젝트 컨벤션대로 자동화 테스트 없이 수동 검증한다.

**Tech Stack:** 순수 HTML/CSS/바닐라 JavaScript (정적 리소스), node 내장 테스트 러너 (`node --test`).

**Spec:** `docs/superpowers/specs/2026-10-30-pvp-mode-design.md`

## Global Constraints

- 로컬(동일 기기) 전용. 온라인/원격 대전은 다루지 않는다.
- PvP 전적은 기록/저장/조회하지 않는다 — PvP 게임 종료 시 `submitResult` 호출을 생략한다.
- 기존 쉬움/어려움(vs 컴퓨터) 모드의 동작과 전적 기록 로직은 바꾸지 않는다.
- 백엔드(`/api/results`, `/api/stats`, `Difficulty` enum, `schema.sql`)는 변경하지 않는다.
- 기존 프런트엔드 구조(단일 IIFE, 절차적 스타일)를 유지한다.
- `game.js`는 기존에도 자동화 테스트가 없는 DOM 배선 코드다 (순수 로직만 `game-logic.js`/`ai.js`에서 `node --test`로 검증됨). 이 패턴을 유지한다 — `game.js` 변경은 수동 브라우저 검증으로 확인한다.

## Review Focus

- PvP 모드에서 보드가 꽉 찼지만 승자가 없을 때 "무승부입니다." 배너가 뜨는지 (draw 처리 누락 가능성이 가장 큼).
- PvP "다시 시작" 클릭 시 턴이 항상 X부터 다시 시작하는지 (턴 상태가 이전 게임에서 새어나올 가능성).
- "모드 변경"으로 모드 선택 화면에 돌아갔을 때 턴 표시가 화면에 남아있지 않는지.
- 쉬움/어려움 모드로 게임할 때 여전히 `submitResult`가 호출되고 전적이 쌓이는지 (PvP 분기 추가로 인한 회귀 가능성).
- 게임이 끝난 뒤(결과 배너가 보일 때) 턴 표시가 같이 사라지는지 (끝난 게임에 "X 차례"가 남아있으면 혼란).

### Task 1: `game-logic.js`에 턴 교대·결과 메시지 순수 함수 추가

**Files:**
- Modify: `src/main/resources/static/js/game-logic.js`
- Test: `src/test/js/game-logic.test.js`

**Interfaces:**
- Produces: `getNextSymbol(symbol: 'X' | 'O') -> 'X' | 'O'` — 반대 기호 반환.
- Produces: `getResultMessage(mode: 'EASY' | 'HARD' | 'PVP', winner: 'X' | 'O' | 'draw') -> string` — PVP는 승자 기호 기준 문구, EASY/HARD는 기존 사람(X) 기준 문구(`'승리했습니다!'` / `'패배했습니다.'` / `'무승부입니다.'`)를 반환. PVP의 draw도 `'무승부입니다.'`.
- 두 함수는 기존 `createEmptyBoard`/`getAvailableMoves`/`checkWinner`/`getRandomMove`와 같은 방식으로 `module.exports`에 추가된다.

});

test('getNextSymbol returns X when given O', () => {

});

test('getResultMessage for PVP mode uses winner-based wording', () => {

### Task 3: `game.js`에 PvP 모드 배선 (턴 교대, 컴퓨터 응수/전적 저장 생략)

**Files:**
- Modify: `src/main/resources/static/js/game.js`

**Interfaces:**
- Consumes: `getNextSymbol(symbol)`, `getResultMessage(mode, winner)` (Task 1), `#pvp-button`, `#turn-indicator` (Task 2).
- Produces: 없음 (최종 사용자 기능).

- [ ] **Step 1: 상태 변수와 DOM 참조 추가**

파일 상단, 기존 버튼 참조들 옆에 `var pvpButton = document.getElementById('pvp-button');`과 `var turnIndicator = document.getElementById('turn-indicator');`를 추가한다. `var gameOver = true;` 근처에 `var currentTurn = HUMAN;`를 추가한다 (PvP에서 현재 차례를 추적; 다른 모드에서는 사용하지 않음).

- [ ] **Step 2: `startGame`에서 턴 상태 초기화 및 PvP 버튼 연결**

`startGame(selectedDifficulty)` 안, `gameOver = false;` 다음에 `currentTurn = HUMAN;`를 추가하고, `render()` 호출 전후 어딘가에 턴 표시를 갱신하는 `updateTurnIndicator()` 호출을 추가한다 (Step 4에서 정의). `pvpButton`에 `startGame('PVP')`를 호출하는 클릭 리스너를 `hardButton`과 같은 방식으로 추가한다.

- [ ] **Step 3: `handleCellClick`에 PvP 분기 추가**

현재 로직(사람 수 → 승자 확인 → 컴퓨터 수 → 승자 확인)을 `difficulty !== 'PVP'`일 때만 타도록 감싸고, `difficulty === 'PVP'`일 때는: 클릭한 칸이 비어 있으면 `board[index] = currentTurn`로 두고 `render()`, `checkWinner(board)`로 승자 확인 — 승자가 있으면 `finishGame(winner)` 호출, 없으면 `currentTurn = getNextSymbol(currentTurn)` 후 `updateTurnIndicator()` 호출.

- [ ] **Step 4: `updateTurnIndicator()` 함수 추가**

`difficulty === 'PVP' && !gameOver`일 때만 `turnIndicator`를 보이게(`classList.remove('hidden')`) 하고 텍스트를 `currentTurn + ' 차례'`로 설정, 그 외엔 `classList.add('hidden')`으로 숨긴다.

- [ ] **Step 5: `finishGame`을 `getResultMessage` 사용하도록 교체**

`finishGame(winner)` 내부의 `if/else if/else`로 `outcome`과 `resultBanner.textContent`를 각각 정하던 로직을, `resultBanner.textContent = getResultMessage(difficulty, winner);`로 교체한다. `outcome` 계산과 `submitResult(difficulty, outcome).then(refreshStats)` 호출은 `difficulty !== 'PVP'`일 때만 실행되도록 감싼다 (PVP면 전적 저장 호출 자체를 건너뛴다). `finishGame` 끝에서 `updateTurnIndicator()`를 호출해 턴 표시를 숨긴다 (`gameOver`는 이미 `true`로 설정돼 있으므로 `updateTurnIndicator`가 자동으로 숨김 처리).

- [ ] **Step 6: `returnToDifficultySelect`에서 턴 표시 숨김**

`returnToDifficultySelect()` 안에서 `turnIndicator.classList.add('hidden')`을 추가해, 모드 선택 화면으로 돌아갈 때 이전 턴 표시가 남지 않게 한다.

- [ ] **Step 7: 수동 브라우저 검증**

Run: `./gradlew bootRun` 후 `http://localhost:8080` 접속.

1. "사람 vs 사람" 클릭 → 보드가 나타나고 "X 차례"가 표시됨.
2. 빈 칸 클릭 → X가 놓이고 표시가 "O 차례"로 바뀜. 다음 클릭 → O가 놓이고 다시 "X 차례"로 바뀜 (컴퓨터가 자동으로 두지 않음).
3. 한쪽이 한 줄을 완성할 때까지 진행 → "X 승리!" 또는 "O 승리!" 배너가 뜨고 턴 표시가 사라짐. 쉬움/어려움 전적 패널 숫자는 변하지 않음(네트워크 탭에서 `/api/results` 호출이 없는지 확인).
4. 무승부가 나는 수순으로 두면 "무승부입니다." 배너가 뜸.
5. "다시 시작" 클릭 → 보드가 비워지고 턴 표시가 다시 "X 차례"부터 시작함.
6. "모드 변경" 클릭 → 모드 선택 화면으로 돌아가고 턴 표시가 보이지 않음.
7. "쉬움" 또는 "어려움"으로 한 판을 플레이해 기존처럼 전적이 집계되는지 확인 (회귀 확인).
